# Profile — Block-Derived SVG Orbitals (placeholder)

**Status: placeholder.** A Block-Derived SVG Orbital is a Data-Rendered SVG Orbital ([Profile 1](data-rendered-svg.md)) whose image is drawn from a record of one Bitcoin block instead of from a seed and traits: for example a map of the block, one square per transaction, sized from each transaction's output value. The picture is fixed by the block before anything is minted, so there are no traits to roll and nothing to reveal, and a reader who holds the block can recompute what the contract holds. A contract cannot read the transactions of a past block, so the record is written when the collection is created. It can be small, since a few bits per transaction are enough for a map, but it is stored, and making it checkable is what a profile for this kind has to do. To be a profile, this kind would have to guarantee at least: both MUSTs of Profile 1; that the collection names its block, by height and hash, from a view; that the derivation is published and is a pure function of the block, saying which fields of the block's transactions are read and how they become the record; that the record is readable from a view, so that a reader can recompute it from the block and compare; and that the image is a pure function of that record. It would also have to say what a reader does when the record and the block disagree, because nothing in the contract can check the block itself, and how such a collection sits with core principle 5, which speaks of traits seeded by the mint, when here nothing is seeded. Under nesting ([STANDARD §12](../STANDARD.md#12--nesting)) the collection is level 1 and its per-transaction pieces are level 0; a piece's image would be the collection's image with that piece's transaction marked. This profile is unwritten until a collection implements it on a chain an independent reader can reach and it is measured; propose it by PR.
